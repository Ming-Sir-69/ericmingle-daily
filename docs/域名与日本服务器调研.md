## 域名与主机分别选择

域名由 DNS 连接到托管服务，注册商、后缀和主机所在国家没有必须一致的要求。Cloudflare Registrar 要使用其 nameservers，但可以把记录指向其他云厂商的日本服务器。[Cloudflare 注册限制](https://developers.cloudflare.com/registrar/get-started/register-domain/)

日本服务器承载本次网站无需中国大陆 ICP 备案；当前无需为备案购买大陆服务器。Netlify 的静态网站通过全球 CDN 分发，不能代表固定在日本的服务器，因此原 Netlify 方案暂保留为已有配置，不作为日本托管已经落实的证据。[腾讯云地域与网络说明](https://cloud.tencent.com/document/product/1207/50103/)、[Netlify 部署说明](https://docs.netlify.com/deploy/deploy-overview/)

X 帖子作为方案线索，本次没有执行其中的脚本。历史点赞不等于当前仍处于点赞状态。

一台日本 VPS 可以分别运行私人网站和个人出口节点；Tailscale Exit Node 是可复用的简洁结构。管理员需要允许该出口，客户端也要主动选用，服务器在日本不会让其他设备或 Claude 云端任务自动迁到日本。[Tailscale 官方出口节点说明](https://tailscale.com/docs/features/exit-nodes)

普通日本 VPS 是固定机房 IP，与住宅 IP 不同。静态住宅代理还需核查是否日本、共享或独享，以及前置连接条件。Webshare 的静态住宅产品是托管于服务器的 ISP 代理，不能因其住宅产品宣传覆盖多个国家就推定提供日本固定独享 IP。[Webshare 产品说明](https://help.webshare.io/en/articles/8625115-what-types-of-static-residential-proxies-do-you-have)、[位置与库存](https://help.webshare.io/en/articles/17577830-which-locations-are-available-on-each-plan)

当前调研没有证明任何方案可以避免账号风控，也没有实测从铭哥的 Mac、手机或 NAS 直连日本节点的质量。Linux TCP BBR 与 QUIC 中的 BBR 属于不同实现，原帖关于 BBR 加速任意 UDP 的表述不能直接照用。[Google BBR 项目](https://github.com/google/bbr)
